# Phase 19.3 — authorization matrix

Generated from actual Express mounts and middleware with `node tests/authorization.matrix.js` on 2026-10-14. All 99 API method/path pairs match the existing reviewed service-policy matrix. ALLOW* denotes role eligibility subject to the resource/state condition, not permission to every object. This matrix describes policy; execution evidence and test limits are in [the results report](AUTHORIZATION_TEST_RESULTS.md).

Shared dashboard routes are scoped, not uniformly Admin-only. Technician queue/read policy permits unassigned or own assigned tickets; mutation/upload normally requires assignment. Employee `priorityId` editing on own OPEN/ASSIGNED tickets is intentional. Notification ownership has no Admin bypass. Stateless bearer claims never override the current DB role/activity. Public/cookie auth endpoints are not role-gated bearer APIs.
